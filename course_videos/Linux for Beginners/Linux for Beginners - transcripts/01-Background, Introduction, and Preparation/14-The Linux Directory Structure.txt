Instructor: In this lesson, you'll learn about the Linux directory structure where you can find different components of the Linux operating system, and you'll see how applications can use the same conventions as the Linux operating system for their directory structure as well. So why should you even care about the Linux directory structure? Well, having a solid understanding of the directory structure will increase your overall knowledge of Linux, help you navigate the file system, save you time because you know where system components and files are most likely to be, and helps you in troubleshooting issues, because you'll be able to find log files and configuration files. Typically, applications use the same standards for their directory structure, so by learning the Linux file system layout, you'll be able to use and administer applications more effectively. Overall, your experience of using a Linux system will be improved by understanding the key ways Linux organizes its files and directories. First, I would like to share with you some of the most common top level directories that you'll see when using the Linux operating system. There are several top level directories to be aware of but these first few are the most important, and they're the ones you'll interact with the most often. The Linux directory structure is like a tree. The base of the Linux file system hierarchy begins at the root. Directories will start to branch off the root, but everything starts at root. The directory separator in Linux is symbolized by a forward slash and is often abbreviated to just slash. So root is often referred to as slash, as there are no other directories above it. If you hear someone say, well look and slash or that file is in slash, they are referring to the root directory. Bin or /bin or /bin is where you'll find binary files are executable programs. Programs are written in source code, which is human readable text. Those text files are then compiled into machine readable binaries. They're called binaries because machine code is a string of zeros and ones. Keep in mind that applications that you can run are sometimes located in /bin. /etc or etc is where you'll find configuration files. Configuration files control how the operating system or applications behave. For example, there's a configuration file in /etc that tells the operating system whether to boot into text mode or graphical mode. /home is where user home directories are stored. So for example, my home directory would be /home/Jason. Linux systems can and often do have multiple users or multiple user accounts, and the home directory is where you can separate your data from another accounts data. You can store anything you want in your home directory like documents, music files or vacation pictures. Opt is where optional or third party software is stored. Opt is for software that is not bundled with the operating system. For example, Google Earth is not part of the standard Linux operating system so that application would typically be installed in /opt. /tmp is called tmp and it's for temporary space. Most Linux distributions clear /temp at boot time so if you put files in tmp and the Linux server or your Linux desktop gets rebooted, the files you stored in tmp will be gone. Tmp is a great place to store temporary files, but don't put anything in tmp that you want to keep long term. /usr is called the usr directory and it's where user related programs live. Each one of these directories can have sub directories. For example, we already talked about /home /usr name. The user directory is no different and there will be a subdirectory structure within /usr. For example, you'll find binary programs and executables located in /usr/bin. /var also called var is for variable data. Think of things that change often. Things that change often on a Linux system are typically log files that are generated either by the operating system itself or applications. In Linux, we typically talk about directories, but other operating systems may call the similar concept folders. If you think about it in terms of folders, then slash or root is the main folder and each one of these r sub folders. Again, folder and directory is often used interchangeably but in Linux we're going to use the term directory. Let's switch gears a little bit and start talking about application directory structures. You'll find that some applications that are not bundled with a Linux operating system or distribution are installed in user local, and often they're installed in user local program name. Another common practice is to use the directory /opt/ company name or /opt/ organization name to install software written by a specific company or organization.
